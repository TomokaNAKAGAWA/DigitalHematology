## Q1. 最終セルのコードは何か、どこに何を入力すれば動くか

### コードの目的
検出器 `detect_wbc_boxes` の**見逃し(偽陰性)を目視確認**するためのもの。
1枚のWSIから `N_PATCHES` 枚(既定100)のパッチをランダムに切り出し、検出BBoxを緑枠で描いたPNGを保存する。

- 検出0件のパッチも捨てずに保存する → 「白血球が写っているのに枠がない」パッチを探せる
- ファイル名は `{スライド名}_x{X}_y{Y}_n{検出数}.png`。`_n0.png` だけ見れば未検出パッチを優先確認できる
- 座標選択・検出ロジックは `batch_extract_wbc_patches.py` の関数と同一

### 元のセルが動かなかった理由
元はコマンドライン用スクリプト(`python inspect_wbc_detection.py --tif-path ...`)をそのまま貼ったもので、notebookでは以下でエラーになる状態だった。

1. `parser.add_argument("/workspace/.../xxx.tif", required=True)` のように、**引数名(`--tif-path`/`--output-dir`)の位置にパスが書かれていた**
2. `__file__` はnotebookに存在しない(`sys.path.append(...)` で `NameError`)
3. `argparse` はJupyterカーネルの余分な引数を拾ってエラーになる

## Q4. 描画した画像をYOLOの学習データにするには、どんなBBoxが必要か。緑枠で囲むだけでよいか

**緑枠を描き込んだ画像はそのままでは学習データにならない。** YOLOは画像中の線ではなくラベルファイルの座標を正解として使う。枠を描き込んだ画像で学習すると緑の線自体を手がかりに覚えてしまうおそれがあるため、緑枠画像は**人が目視確認するための用途**に限る。

### 必要な形式
```
dataset/
  images/train/xxx.png      # raw patch, no boxes drawn
  labels/train/xxx.txt      # same file name, .txt
  images/val/...
  labels/val/...
  data.yaml
```

ラベル `.txt` は1枠1行で `class_id x_center y_center width height`(すべて画像サイズで割って0〜1に正規化)。例: `0 0.4531 0.6203 0.1250 0.1406`

`detect_wbc_boxes` の `(x_min, y_min, x_max, y_max)` からの変換(パッチ640px):
```python
xc = (x_min + x_max) / 2 / 640
yc = (y_min + y_max) / 2 / 640
bw = (x_max - x_min) / 640
bh = (y_max - y_min) / 640
```

白血球が写っていない背景パッチは**空の `.txt`** を置けば学習に使える。

```yaml
path: /path/to/dataset
train: images/train
val: images/val
names:
  0: WBC
```

### 枠の付け方のルール
- **画像内の白血球をすべて囲む**(囲み漏れは「白血球ではない」と教えることになる。`_n0` の確認が重要な理由)
- **細胞全体(核+細胞質)をぴったり囲む**。現検出器は核の青みベースなので、細胞質のはみ出しや余白の過大は人手修正が必要
- **1細胞1枠**。現検出器は近接ヒットを合体させるため、接した細胞が1枠になる誤りが起きやすい
- **白血球以外(血小板・青みの強い赤血球)は囲まない**
- **パッチ端で切れた細胞の扱いは一つに決めて統一する**
- 枠は軸に平行な長方形(回転枠ではない)

### 想定フロー
1. `batch_extract_wbc_patches.py` で、枠なしの元パッチPNGと下書き枠 `*_draft.json`(`boxes_xyxy`)を出力する(既に実装済み)
2. 下書きをCVATやLabel Studioに読み込み、人手で枠を修正する(追加・削除・位置調整)
3. 修正済みの枠をYOLO形式でエクスポートする
4. スライド単位で train と val に分けて学習する

cell-24の緑枠画像は、この手前で「検出器がどれくらい見逃すか、どんな誤りをするか」を把握するために使う。

## Q5. inspect_wbc_detection.py と extract_yolo_patches.py はそれぞれ何か。方針は正しいか

前提: 100枚の目視確認(cell-24)で偽陽性・偽陰性はなかった。

### 2つのスクリプト(experiments/261030/)
- `inspect_wbc_detection.py`: 目視確認用。cell-24の元ファイル。ランダムに切り出したパッチに緑枠を描いてPNG保存する。**学習データには使えない**
- `extract_yolo_patches.py`: YOLO学習データ書き出し用で、やりたいことに近い
  - 出力: `images/<slide>/*.jpg`(枠なし), `labels/<slide>/*.txt`(`0 cx cy w h`), `dataset.yaml`
  - `--negative-ratio` で陽性/陰性比を指定。`--mode random`(乱択)と `--mode grid`(組織領域を640×640で敷き詰めて全マス検出)がある
  - argparseと `sys.path.append(... __file__ ...)` を使うため、ノートブックではそのまま動かない

### 方針(1スライド全域を640×640グリッドで読み、陽性/陰性比を指定してYOLO形式で書き出す。まず1枚で試す)
基本的に正しい(`--mode grid` と同じ考え方)。注意点:
1. **ラベルの質は検出器の質が上限**。全域にすると未確認の領域(細胞が密な所、塗抹の端、染色ムラ)の誤りも混ざるので、一部を抜き取り確認する
2. **枠の大きさ**: 核の青みにsize/2の余白を足した枠。細胞質まで囲めているか確認しておく(YOLOの枠の大きさはこれに従う)
3. **「全領域」の範囲**: 最大の組織領域の外接矩形内で、組織が50%以上写るマスのみ。端の640px未満の余りは捨てる。陰性は「組織はあるが白血球がない所」になる
4. **境界で切れた白血球**: 重なりなしの敷き詰めなので、両側のパッチに部分枠として入る。最初はこのままでよい

実行時間の目安: スライド約16,000×227,000px → 最大約8,800マス。1スライド数十分以上かかる可能性がある。

# 続き: 細胞質が緑枠からはみ出す問題と、枠の大きさ・余白の決め方

対象: `experiments/261021/261021_pickup-wbc_Re-nakagawa.ipynb` の cell-24(100枚の目視確認)、`detect_wbc_boxes`(`experiments/261021/batch_extract_wbc_patches.py:195-241`)

## Q7. 目視確認の出力で、細胞質の一部が緑枠からはみ出している白血球があった。どうすべきか。YOLOでは枠に含まれない部分は白血球と認識されないのか

### YOLOの学び方
- 枠は「この長方形が白血球」という意味で、枠内のピクセルだけを白血球として覚えるわけではない。枠の外も周りの情報として見るので、細胞質がはみ出していても検出できなくなるわけではない
- 問題になるのは**枠の大きさ**: 小さめの枠で学習すると、モデルも小さめの枠を出す。全体を囲めている枠とはみ出す枠が混ざると、答えがぶれたデータになる。人手で細胞全体を囲んだ正解で評価すると IoU が下がる

### はみ出す原因
現在の枠は、**核の青み**の強い 30×30 の窓(`blue_mean > 180 and red_mean < 130`)が当たった範囲に `size/2 = 15px` を足しただけで、細胞質は見ていない。核に比べて細胞質が広い細胞(単球、好中球の一部、大型リンパ球など)でははみ出しやすい。

### 選択肢
| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A. 余白を一律に広げる | 余白に `pad` 引数を足す | 簡単。100枚ですぐ確認できる | 小型細胞で枠が大きすぎる。赤血球が入る |
| B. 細胞質も含めて枠を作り直す | 核の周りで「背景でも赤血球でもない色」の範囲を広げて取る | 細胞ごとに合った枠 | 赤血球と接した細胞質の分離が難しく、閾値の調整が要る |
| C. 人手で直す | CVATなどで修正する | 最も正確 | 手間がかかる |

この時点の提案: まず A を試し、val/test だけ C にする。B は A で足りないと分かってから。

## Q8. 最終目標は白血球の検出で、枠で囲むことではないが大丈夫か。余白 `size/2` はベストか(固定値でも根拠のある値にしたい)。枠が大きすぎる場合のデメリットは何か

### 1. 目標が検出なら、枠が小さめでも大丈夫か → ほぼ大丈夫
- 白血球を見つけられるかどうかは、主に**核の見た目**を覚えられるかで決まる。今の枠も核を中心に囲んでいるので、位置は学習できる。白血球の有無や数を見る目的なら、実用上の差は小さい
- 枠の大きさが効いてくるのは次の3つの場合:
  1. **評価との不一致**: 人手で「細胞全体」を囲んだ正解で評価すると、IoU が閾値を下回り「見逃し」と数えられる。学習と評価で同じ枠の定義を使えば問題ない
  2. **後で枠を切り出して分類する場合**: 細胞質(顆粒や色)は種類を見分ける手がかりなので、欠けると分類に響く
  3. **枠ごとのばらつき**: 一律に小さいことより、全体を囲めている枠とはみ出す枠が混ざっていることのほうが有害
- 検出という目的に対しては、余白よりも**近い白血球同士が1枠にまとまる処理**(`merge_margin = 2*size` = 60px)の影響が大きい。2個が1個と数えられ、検出数が直接ずれる

### 2. 余白 `size/2` に根拠はあるか → ない
`size/2` は30×30の窓をずらして調べる仕組みの都合で入った値で、細胞の大きさとは関係がない。根拠のある値にする方法:

- **(a) 物理的な大きさから決める**: WSIメタデータの画素の大きさ(`openslide.mpp-x`、µm/px)と、文献にある細胞の直径(目安としてリンパ球 7〜10µm、好中球 10〜12µm、単球 12〜20µm)から px に換算する。説明しやすいが、核から細胞の外側までの幅は種類ごとに大きく違い、1つの値に決めにくい。文献値と実際の標本が合う保証もない
- **(b) 自分のデータで測って決める【推奨】**:
  1. 種類に偏りがないよう 50〜100個の白血球を選び(cell-24 の100枚から選べる)、人手で「細胞全体の外接矩形」を付ける
  2. 検出器の「核ベースの枠」と比べ、細胞ごとに必要だった余白を測る
  3. 固定値(px)と、核の枠の大きさに比例させる方法(×1.3 など)を比べる。判断基準は「95%の細胞で細胞質が枠に収まる最小の値」や「人手の枠との IoU の中央値が最大になる値」
  - 「n=○○個の手作業の枠に対して95%を含む値」という形で、方法の節にそのまま書ける根拠になる。(a) の換算値と大きくずれていないかも確認しておく

### 3. 枠を大きくしすぎた場合のデメリット
| 観点 | デメリット |
|---|---|
| 密集した領域での見逃し | **最大の問題**。NMS で重なりの大きい枠は1つだけ残るため、近くにある2個の白血球の片方が消される。数え落としに直結する |
| 枠の境界に手がかりがない | 小型細胞では枠の端が背景や赤血球の上になり、枠の大きさの予測が安定しない。全細胞を同じ固定サイズで囲めば「中心+一定の大きさ」を覚えるだけになり、この問題は消える |
| 大きさの情報が消える | 枠の大きさが細胞の大きさを反映しなくなる。大きさを分類の手がかりにする用途(小型/大型リンパ球など)で困る |
| パッチ端での切れ | 枠が大きいほど 640px パッチの端にかかりやすく、切れた枠が増える |
| 後段の切り出しに余計なものが入る | 隣の細胞や赤血球が入り、分類の邪魔になる |
| 評価値の解釈 | 人手の枠や他のデータセットと定義が違い、mAP を比べにくい |

枠が小さすぎる場合のデメリットは、細胞質の欠けと評価との不一致(1を参照)。

### まとめ(方針案)
- **枠の定義は「細胞全体の外接矩形」にそろえる**。人手の枠と比べられ、細胞質も残るので後で分類に進むときにも困らない
- **余白の値は (b) の方法で、少数の手作業の枠から測って決める**
- 大きい白血球に合わせて全体を大きくする方法は、密集した領域での見逃しが起きるので避ける。簡単に済ませたい場合だけ、「固定サイズの枠」という別の設計として検討する
